### Deliverable 1 — `phase-planner` agent prompt (v1)

**Target**: NEW file at `/root/projects/phi/.claude/agents/phase-planner.md` (initial v1).

**Shape** (mirror the structure of `chunk-planner.md` but at the milestone tier):
- YAML frontmatter (`name`, `description`, `model: opus`, `tools: Read, Grep, Glob, Bash, Write`, `version: 1`).
- **Project context** — PROJECT_ROOT-aware path resolution (baby-phi default; i-phi conventions noted) so the agent works on either submodule.
- **Inputs the orchestrator provides** — milestone tag (e.g., `M6`); pointer to the base build plan section (lines/file); pointer to any prior-milestone forward-scope §M*+ markers; pointer to a pre-scoping alignment audit doc (if available); concept-doc roots to walk.
- **Procedure** — 6 steps:
  1. Read base build plan section + prior forward-scope §M*+ markers + alignment audit + concept docs the milestone touches.
  2. Cross-reference deferral markers against current code state (greps for `[PLANNED]` tags pointing at the target milestone; greps for `M<N>-DEFERRED-` references).
  3. Enumerate carryovers (e.g., `C-M6-N` items defined in the base build plan that the prior milestone deferred).
  4. Decompose milestone scope into chunks (CH-NN). Each chunk gets: title, severity (LOW/MEDIUM/HIGH), effort estimate (engineer-days), concept docs touched, prerequisites, drift IDs closed (if applicable).
  5. Build dependency graph (critical path + parallelizable foundation work).
  6. Capture open questions (decisions the user must lock before chunk-planning opens).
- **Output handoff format** — verbatim 6-line return block (forward-scope path written, chunk count, total effort, dep-graph summary, open questions count, recommended chunk-zero — i.e. which CH-NN to open plan-mode on first).
- **Quality bar** — must-pass checks parallel to chunk-planner v21's quality bar (no fabricated drift IDs; all concept-doc citations must verify via grep; effort estimates carry an explicit upper-band; per-chunk severity column populated).
- **Constraints** — read-only on source code; only Write target is the forward-scope file path; no commits; no ExitPlanMode.
- **Memory + repo conventions** — honor `feedback_cargo_jobs_cap.md`, `feedback_cargo_docker.md`, `feedback_plan_archive_naming.md` (slug-first 8hex), `feedback_thoroughness_over_speed.md`, `feedback_no_verified_headers_in_agents.md` (no verified-header in the agent file itself).

**Standing template the agent consumes**: `baby-phi/docs/specs/plan/forward-scope/22035b2a-remaining-scope-post-m5-p7.md` is the canonical shape (§1 drift-remediation tiers, §2 original milestone scope accounted-for, §3 deferred-milestone markers, §4 dep graph, §5 per-chunk scope summary table, §6 + §7 open questions). The agent's procedure step 6 should produce an output matching this shape exactly.
