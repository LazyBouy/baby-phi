- **Why deferred at CH-28d**: all 4 axes are opt-in feature-work + require architectural-shift prerequisites (long-lived-agent shape OR hook-script dispatch path OR pause/cancel surface) that are out-of-scope for a TECHNICAL-PREREQUISITE absorption chunk. ## Remediation scope (estimate only)

The adoption work decomposes into 4 axis-specific tracks (per phi-core 0.10.0 CHANGELOG activation guidance + baby-phi architectural constraints):

1. **Axis A — `BasicAgent::with_revert_render_policy` live wire-through**: requires baby-phi to instantiate `phi_core::BasicAgent` per request (or per session) — a fundamental architectural shift from the current per-request-stateless posture (per ADR-0034 §D34.6). Estimated effort: ~3-5 ed for the long-lived-agent shift alone (BasicAgent lifecycle management + state transfer + cleanup); ~0.3-0.5 ed for the per-policy tunable wiring at the `launch.rs:592` site once long-lived-agent exists. The Composition I `Lesson`/`Note` trunk-context tag rendering tunability is the user-visible feature; operator can adjust decay window policy via baby-phi config TOML.

2. **Axis B — `BasicAgent::current_tool_timeout(&self) -> Option<Duration>` pause-time tool-timeout introspection**: requires Axis A (long-lived-agent shape — baby-phi must hold the `Arc<dyn Agent>` across loop turns to call `current_tool_timeout()` on it) + a baby-phi pause/cancel surface that doesn't exist today. Estimated effort: ~2-4 ed for the pause/cancel surface design + ~0.3-0.6 ed for the `current_tool_timeout()` consumption at the pause-acknowledgement site. The `PauseAcknowledged.estimated_completion_ms` UI surface is the user-visible feature; operator can see remaining tool-execution time before pause completes.

3. **Axis C — `phi_core::agent_loop::script_callback::detect_interpreter` `pub`-shim adoption**: independent of Axes A/B/D — requires only a hook-script dispatch path inside baby-phi. Currently baby-phi has no `.sh`/`.py`/`.js` hook-script dispatch path; the entire feature axis is out-of-scope at v0. Estimated effort: ~1-2 ed for a minimal hook-script dispatch path consuming `detect_interpreter` (interpreter detection + script execution + result capture). The user-visible feature is hooks dispatching via interpreted scripts (shell/Python/JS) instead of binary executables only.

4. **Axis D — `CurrentToolExecution` struct standalone consumption (separate from the `current_tool` slot in `AgentLoopConfig`)**: depends on Axis A (long-lived-agent shape to hold the `Arc<Mutex<...>>` slot across loop turns) + Axis B (the introspection use case for reading the slot). Once both prerequisites exist, the standalone consumer is a thin layer (~0.3-0.6 ed for an audit-event projection emitting `ToolExecutionObserved { session_id, turn_id, tool_name, started_at, elapsed_ms }` for operator dashboards). The user-visible feature is per-tool-call observation surface for operators / debug UIs.

**Aggregate effort estimate**: ~7-15 ed for full closure (all 4 axes adopted). Partial closures are independently schedulable:
- **Axis C alone**: ~1-2 ed (independent of Axes A/B/D; can land as a standalone FUNCTIONAL chunk).
- **Axes A + B + D bundle**: ~6-10 ed (shared long-lived-agent prerequisite; natural cluster for a single architecture-shift chunk).
- **Axis A alone**: ~3.5-5.5 ed (long-lived-agent shift + per-policy tunable wiring; defers Axes B + D).

**Implementation chunk**: **M7+-FUTURE-ARCHITECTURE-SHIFT-OR-OBSERVABILITY-ADOPTION** (placeholder; no CH-NN slot reserved at CH-28d close — future planning session decides per-axis routing). Chunk-planner v13 non-terminal-drift rule satisfied via the explicit-named-placeholder (NOT `TBD`).

**Dependencies on other drifts**: tangentially related — `D-PHICORE-08-FOLLOWUP-01` (Composition I adoption from CH-28b) and `D-PHICORE-09-FOLLOWUP-01` (per-turn debug capture adoption from CH-28c). All 3 drifts are M6+/M7+ feature-adoption deferrals from consecutive phi-core breaking-change absorption chunks. They may bundle into a single "M7+ phi-core feature adoption" omnibus chunk if planning capacity allows. In particular: Axis A (revert-render-policy wire-through) DEPENDS on `D-PHICORE-08-FOLLOWUP-01` closure (Composition I revert mode must be enabled before kind-aware decay-window tag rendering activates — `RevertRenderPolicy` only takes effect when `active_node_id.is_some()`).

**Risk to concept alignment if deferred further**: LOW. All 4 axes are opt-in features; deferring them further preserves the pre-0.10.0 posture (no kind-aware tag rendering; no per-tool-call introspection; no hook-script dispatch; no `CurrentToolExecution` standalone consumption). The only opportunity cost is operator tooling ergonomics + tunability of Composition I tag rendering (which is itself opt-in upstream + deferred at baby-phi). No user-visible degradation if deferred; just a missed operator-tooling + architectural-flexibility enhancement.
